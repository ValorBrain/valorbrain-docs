## Hospedado vs on-premise

**Hospedado (comece por aqui):** nenhum engine na sua máquina. O harness fala
com o MCP em `https://mcpbrain.valor.digital/mcp` com um token `vbm_` (o
`mcp_token` do signup, ou um criado em
[Settings → MCP tokens](https://valorbrain.valor.digital/settings/mcp-tokens)),
ou com a REST em `https://valorbrain-api.valor.digital`, com o mesmo `vbm_` ou
com a chave legada `vb_agent_` (a `api_key` do signup). O MCP aceita só `vbm_`:
uma chave `vb_` no MCP volta `401 wrong_credential_type`.

Qualquer cliente que só fala stdio usa `npx -y @valorbrain/cli mcp` como
comando do servidor. A instalação completa com regras e hooks, opcional, é
`npx -y @valorbrain/connect@latest --token <vbm_…>`.

**On-premise (Enterprise):** o engine na sua rede é parte do plano
Enterprise — não existe versão comunitária ou self-service, nem `docker
compose up` público; a implantação é acompanhada pela nossa equipe.
[O que o Enterprise inclui](https://valorbrain.valor.digital/enterprise).

## O loop de qualidade (todo harness)

1. **Consulte antes de responder** — a memória manda na operação; os dados de
   treino, não.
2. **Declare o que você usou** — `memory_used` com os docids em que você se
   apoiou. Quando o humano confirmar ou corrigir, passe `verdict`.

Se um README mandar rodar `valorbrain setup harness <name>`, esse subcomando
**não** existe na CLI publicada. Use a página daquele harness.
