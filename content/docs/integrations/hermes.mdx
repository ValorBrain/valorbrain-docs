O Hermes conversa com o ValorBrain como **MemoryProvider**, não como um cliente
MCP genérico com uma lista fixa de ferramentas.

## Token

```bash
npx -y @valorbrain/cli@latest init --agent --agent-caller hermes --json
```

Use o `mcp_token` (`vbm_…`). Com conta, crie o token em
[Settings → MCP tokens](https://valorbrain.valor.digital/settings/mcp-tokens).

## Hermes hospedado

O instalador escreve a config do plugin para você:

```bash
npx -y @valorbrain/connect@latest --token <vbm_…> --harness hermes
hermes memory setup        # escolha valorbrain
```

Providers de memória são ativados por `memory.provider`, não por
`plugins.enabled`. Sem engine local, o provider cobre as ferramentas e os
hooks de ciclo de vida (bootstrap, contexto por turno, extração no fim da
sessão), que rodam no engine hospedado.

Só MCP, sem o plugin: use o mesmo caminho de qualquer cliente —
`https://mcpbrain.valor.digital/mcp` com `Authorization: Bearer <vbm_…>`, ou
`npx -y @valorbrain/cli mcp` via stdio.

## On-premise (Enterprise)

Numa máquina que já tem o engine, o plugin vem da árvore do engine
(`src/hermes/` → `~/.hermes/plugins/valorbrain`). O repositório público de
harness traz uma cópia vendorizada: `./install.sh hermes` copia o plugin para
`~/.hermes/plugins/valorbrain` sem precisar da árvore do engine.

## Ferramentas

A página de marketing antiga em `/docs` que promete um número fixo de
ferramentas para o plugin nativo está desatualizada. O catálogo vivo é o
[catálogo gerado](/docs/api/generated-mcp); um token novo recebe o toolset
**agent**. Guia: [Ferramentas MCP](/docs/api/mcp-tools).

## Verifique

Chame `memory_prepare`. Para manter a conta além de 30 dias, o humano roda
`npx -y @valorbrain/cli init --email <email>`.
