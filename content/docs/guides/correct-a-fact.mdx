---
title: Correct a wrong fact
description: A document can rank first and still be false. Write a keyed fact. The next session should not repeat the error.
---

1. Retrieve as usual (`memory_retrieve` or CLI `search`).
2. If the human says the value is wrong, do **not** only store another
   prose document. Write a keyed fact:

MCP:

```json
{
  "fact_key": "docs.public.host",
  "fact_value": "https://docs.valor.digital",
  "as_of": "2026-08-30",
  "authority": "human"
}
```

Tool: `upsert_keyed_fact`. For a value that already misled someone,
`assert_authority_correction`.

3. Call `memory_used` with `verdict: "corrected"` on the stale docid.
4. In a **new** session, retrieve the same question. The keyed fact should
   win. If a document still ranks first with the old value, it should
   arrive with a `SUPERSEDED:` line — believe the fact, not the body.

That is correctability. If this loop fails, it is a product defect: say so
with `feedback` rather than working around it.
