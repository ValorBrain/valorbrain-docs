Pacote: [`@valorbrain/cli`](https://www.npmjs.com/package/@valorbrain/cli).
Roda sem instalar com `npx -y @valorbrain/cli@latest <command>`.

```bash
npx -y @valorbrain/cli@latest help --json
```

Aquele JSON é o contrato. Se um blog post ou README citar um subcomando que
não está nesse objeto, o comando não existe. Cada comando e flag, gerado
desse JSON: [Referência da CLI](/docs/cli-reference). Esta página explica o
fluxo; não repete a tabela.

O fluxo de conexão inteiro (token, cliente MCP, verificação, claim) está no
[connect.md](https://valorbrain.com.br/connect.md) e no
[Começo rápido](/docs/quickstart).

## Signup de agente

```bash
npx -y @valorbrain/cli@latest init --agent --agent-caller <agent-name> --json
```

Cria uma conta de agente (shadow tenant) sem email. Com `--json`, imprime um
único objeto JSON com, entre outros campos:

| Campo | O que é |
|---|---|
| `mcp_token` | `vbm_…` — a credencial do cliente: MCP em `mcp_url` e REST do engine. Aparece só nesta resposta. |
| `mcp_url` | `https://mcpbrain.valor.digital/mcp` |
| `api_key` | `vb_agent_…` — chave de conta de agente (legado): **só REST** e claim, em `https://valorbrain-api.valor.digital` |
| `notice` | Instrução do servidor para o agente (o `message` do signup), com o aviso de claim para mostrar ao humano |
| `next_steps` | Os passos seguintes do contrato: comando por cliente, stdio, verificação, claim |

Tudo fica salvo em `~/.valorbrain/config.json` (modo `0600`); os outros
comandos leem dali.

`--agent-caller` é autodeclarado, nunca inferido do ambiente. Esqueceu?
`npx -y @valorbrain/cli identify <agent-name>` faz o backfill idempotente.

## Claim pelo humano

```bash
npx -y @valorbrain/cli init --email <email>
```

Vincula a conta a um email com um código de uso único (OTP por email). Depois
do claim o humano vê as memórias no app e a conta passa dos 30 dias. A
`api_key` e o `mcp_token` **não mudam** e continuam funcionando antes e
depois. Veja [Assumir uma conta de agente](/docs/guides/claim).

## Proxy MCP stdio

```bash
npx -y @valorbrain/cli mcp
```

Proxy stdio ↔ Streamable HTTP para `https://mcpbrain.valor.digital/mcp`. Use
como comando do servidor em qualquer cliente MCP que só fala stdio:

```json
{
  "mcpServers": {
    "valorbrain": {
      "command": "npx",
      "args": ["-y", "@valorbrain/cli", "mcp"]
    }
  }
}
```

Usa o token salvo pelo `init`. `--token <vbm_…>` ou `VALORBRAIN_MCP_TOKEN`
sobrescrevem; `--url` ou `VALORBRAIN_MCP_URL` trocam o endpoint.

O host MCP aceita **só** `vbm_`. Uma chave `vb_`/`vb_agent_` como bearer volta
`401 wrong_credential_type`. Veja [MCP](/docs/mcp).

O `@valorbrain/connect` é outro pacote: o instalador opcional que escreve
servidor MCP, regras e hooks nos harnesses
(`npx -y @valorbrain/connect@latest --token <vbm_…>`). Ele não é o proxy stdio.

## Memória pelo shell (REST)

`add`, `search`, `list` e `status` falam REST com a `api_key`:

```bash
npx -y @valorbrain/cli add "the deploy key lives in the ops vault"
npx -y @valorbrain/cli search "deploy key"
```

O body é armazenado verbatim — sem tradução. Flags de cada comando:
[Referência da CLI](/docs/cli-reference).

## Variáveis de ambiente

| Variável | Valor | Uso |
|---|---|---|
| `VALORBRAIN_MCP_TOKEN` | `vbm_…` | Token MCP (proxy stdio, clientes HTTP como o Codex) |
| `VALORBRAIN_API_KEY` | `vb_agent_…` | Chave REST (`add`, `search`, …) |
| `VALORBRAIN_API_URL` | URL | Base REST (padrão `https://valorbrain-api.valor.digital`) |
| `VALORBRAIN_MCP_URL` | URL | Endpoint MCP (padrão `https://mcpbrain.valor.digital/mcp`) |
| `VALORBRAIN_TOKEN` | — | **Legado, deprecado.** Ainda aceito com aviso: `vbm_…` vale como token MCP; qualquer outro valor, como chave REST. Migre para as duas variáveis acima. |
| `VALORBRAIN_API_TOKEN` | — | **Legado, deprecado.** Ainda lido como chave REST, com aviso no stderr. Migre para `VALORBRAIN_API_KEY`. |

Ordem: flag (`--api-key`, `--token`, `--url`) → variável de ambiente →
`~/.valorbrain/config.json`.

## On-premise (Enterprise)

```bash
npx -y @valorbrain/cli --url https://your-engine.example.com init --agent
```

Não existe instalador público de uma linha para o engine. On-prem é um plano
Enterprise — [implantação acompanhada pela nossa equipe](https://valorbrain.valor.digital/enterprise) na sua rede.
