## OpenAPI: which file to use

| URL | What it actually is |
|---|---|
| `https://valorbrain-api.valor.digital/openapi.json` | The engine's **public** OpenAPI, no auth needed: client routes only (documents and ingest, conversations, search and retrieve, `memory` prepare/store/recall/used, agent signup/identify/claim, MCP tokens, OAuth, health), generated from the process' route table. The source of this site's REST reference. |
| `https://docs.valorbrain.com.br/openapi.json` | A copy of the above, regenerated at docs build (servers rewritten to valorbrain-api and the local engine). |
| Engine repo `docs/reference/openapi.yaml` | The engine's full contract, admin and operations routes included. For the platform operator only; not published. |
| `https://valorbrain.valor.digital/openapi.json` | The app's OpenAPI: the same engine client routes plus the app's client routes (`POST /api/v1/ingest`, `POST /api/v1/cli/device/code`, `POST /api/v1/cli/device/token`), with the app as server. |

The `@valorbrain/connect` device flow and `fk_` key ingest are app routes on
`https://valorbrain.valor.digital`, not engine routes: they are in the app's
OpenAPI, not in the engine's public spec.

The credential matrix (prefixes, where each one is accepted, client variables,
limits and errors) is served at
[`https://valorbrain-api.valor.digital/.well-known/valorbrain-credentials.json`](https://valorbrain-api.valor.digital/.well-known/valorbrain-credentials.json).
The [Tokens](/en/docs/concepts/tokens),
[Token lifecycle](/en/docs/api/token-lifecycle),
[Rate limits](/en/docs/api/rate-limits) and [Errors](/en/docs/api/errors)
pages are generated from it, and this site publishes the same copy at
[`/valorbrain-credentials.json`](/valorbrain-credentials.json).

To integrate, use the engine's public spec (or this site's copy) and the
[REST endpoints](/en/docs/api/rest) page.
