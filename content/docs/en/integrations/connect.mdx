This is the path [connect.md](https://valorbrain.com.br/connect.md) tells an
agent to follow, here with links into the rest of the docs. At most three
commands: get a `vbm_`, wire the MCP client, call `memory_prepare`.

To have your agent do it on its own, send:

> Connect ValorBrain as your memory: read [https://valorbrain.com.br/connect.md](https://valorbrain.com.br/connect.md) and follow it.

## 1. Get a `vbm_` token

`vbm_` is the client credential: it works on the MCP and on the engine REST
API, and the tenant comes from it (never send `X-Tenant-ID`).

**No account:** the agent creates its own account with one command.

```bash
npx -y @valorbrain/cli@latest init --agent --agent-caller <agent-name> --json
```

The JSON output carries:

| Field | What it is |
|---|---|
| `mcp_token` | The `vbm_…` token. Shown only in this response; the CLI saves it in `~/.valorbrain/config.json`. |
| `mcp_url` | `https://mcpbrain.valor.digital/mcp` |
| `api_key` | Agent account key `vb_agent_…` (legacy): REST and the claim only. On the MCP it gets `401 wrong_credential_type`. |

Unclaimed, both credentials expire after 30 days; see
[Claim an agent account](/en/docs/guides/claim).

**With an account:** create the token in the app, under
[Settings → MCP tokens](https://valorbrain.valor.digital/settings/mcp-tokens).
One token per agent or persona keeps writes attributable, and revoking one
does not break the others.

**No token to paste (OAuth):** claude.ai, ChatGPT and Cursor take the MCP URL
as a custom connector, `https://mcpbrain.valor.digital/mcp`. The client
discovers the authorization server, you consent in the app, and the client
receives its own `vbm_`. Skip to step 3.

## 2. Wire the MCP client

**Claude Code, Codex, Kiro, Gemini CLI and Cursor: one command** installs MCP,
memory rules and hooks. Run it on the CLI's machine and restart the session:

```bash
npx -y @valorbrain/connect@latest --token <vbm_…> --harness <claude-code|codex|kiro|gemini-cli|cursor>
```

Tell your human first: the hooks send the prompt of each turn of the CLI (up to
8,000 characters) to their ValorBrain workspace to fetch memory; no transcript
is sent. After the install, to stop sending the prompt:
`npx -y @valorbrain/connect@latest --harness <id> --prompt off`; to turn the checkpoint off:
`npx -y @valorbrain/connect@latest --harness <id> --checkpoint off`. Except on Gemini CLI,
`VALORBRAIN_SEND_PROMPT=off` and `VALORBRAIN_CHECKPOINT=off` in the CLI's
environment do the same; Gemini CLI strips the environment of its hooks, so
there only the saved choices work. To drop only the hooks, run the install
again with `--mcp-only`; `npx -y @valorbrain/connect@latest --harness <id> --remove`
undoes everything (MCP entry, rules, hooks and saved credentials).
Per-CLI details: [What leaves your machine](/en/docs/concepts/what-leaves-your-machine).

**No hooks (the human declined):** the same command with `--mcp-only` installs
the MCP server and the rules, no hooks; nothing is sent per turn. On Hermes,
which has no hooks, the memory plugin keeps sending the prompt (use `--prompt off`).

```bash
npx -y @valorbrain/connect@latest --token <vbm_…> --harness <id> --mcp-only
```

**Other clients, or MCP by hand: MCP server only.** MCP server over Streamable HTTP at `https://mcpbrain.valor.digital/mcp`, with
`Authorization: Bearer <vbm_…>`.

**Claude Code** ([full page](/en/docs/integrations/claude-code))

```bash
claude mcp add --transport http --scope user valorbrain https://mcpbrain.valor.digital/mcp --header "Authorization: Bearer <vbm_…>"
```

**Codex** ([full page](/en/docs/integrations/codex))

```bash
export VALORBRAIN_MCP_TOKEN=<vbm_…>
codex mcp add valorbrain --url https://mcpbrain.valor.digital/mcp --bearer-token-env-var VALORBRAIN_MCP_TOKEN
```

**Gemini CLI** ([full page](/en/docs/integrations/gemini)): `~/.gemini/settings.json`

```json
{"mcpServers":{"valorbrain":{"httpUrl":"https://mcpbrain.valor.digital/mcp","headers":{"Authorization":"Bearer <vbm_…>"}}}}
```

**Cursor** ([full page](/en/docs/integrations/cursor)): `~/.cursor/mcp.json`

```json
{"mcpServers":{"valorbrain":{"url":"https://mcpbrain.valor.digital/mcp","headers":{"Authorization":"Bearer <vbm_…>"}}}}
```

**VS Code** ([full page](/en/docs/integrations/vscode)): `.vscode/mcp.json`

```json
{"servers":{"valorbrain":{"type":"http","url":"https://mcpbrain.valor.digital/mcp","headers":{"Authorization":"Bearer <vbm_…>"}}}}
```

**claude.ai / Claude Desktop:** Settings → Connectors → Add custom connector →
URL `https://mcpbrain.valor.digital/mcp`. Sign-in is by OAuth; there is no
token to paste. Details in [Connectors](/en/docs/integrations/connectors).

**Any stdio-only client:** use this as the server command (it uses the token
saved by `init`):

```bash
npx -y @valorbrain/cli mcp
```

**Full install, optional:** sets up MCP, memory rules and hooks for every
agent detected on the machine.

```bash
npx -y @valorbrain/connect@latest --token <vbm_…>
```

## 3. Verify

Call the MCP tool `memory_prepare`. If it answers with your identity and the
workspace, memory is on.

## If you get `wrong_credential_type`

The MCP takes only `vbm_`. A `vb_agent_`, `vb_<slug>_` or `fk_` key as an MCP
bearer gets `401` with `error: "wrong_credential_type"`. Swap it for the
signup's `mcp_token` or a token created under Settings → MCP tokens; keep the
`api_key` for REST. Every other code is in the
[error catalog](/en/docs/api/errors).

## Environment variables

| Variable | Holds |
|---|---|
| `VALORBRAIN_MCP_TOKEN` | `vbm_` token |
| `VALORBRAIN_API_KEY` | `vb_agent_` REST key |
| `VALORBRAIN_API_URL` | `https://valorbrain-api.valor.digital` |
| `VALORBRAIN_MCP_URL` | `https://mcpbrain.valor.digital/mcp` |
