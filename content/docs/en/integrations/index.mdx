## Hosted vs on-premise

**Hosted (start here):** no engine on your laptop. The harness talks to MCP at
`https://mcpbrain.valor.digital/mcp` with a `vbm_` token (the signup's
`mcp_token`, or one created under
[Settings → MCP tokens](https://valorbrain.valor.digital/settings/mcp-tokens)),
or to REST at `https://valorbrain-api.valor.digital` with the `vb_agent_` key
(the signup's `api_key`). Each credential works only on its own host: a `vb_`
key on MCP gets `401 wrong_credential_type`.

Any stdio-only client uses `npx -y @valorbrain/cli mcp` as the server
command. The optional full install with rules and hooks is
`npx -y @valorbrain/connect@latest --token <vbm_…>`.

**On-premise (Enterprise):** the engine on your network is part of the
Enterprise plan — there is no community or self-service edition and no public
`docker compose up`; deployment is accompanied by our team.
[What Enterprise includes](https://valorbrain.valor.digital/en/enterprise).

## The quality loop (every harness)

1. **Consult before answering** — memory is authoritative about the
   operation; training data is not.
2. **Declare what you used** — `memory_used` with the docids you relied on.
   When the human confirms or corrects, pass `verdict`.

If a README tells you to run `valorbrain setup harness <name>`, that
subcommand is **not** on the published CLI. Use the page for that harness
instead.
