The hosted API at `valorbrain-api.valor.digital` is the zero-setup path. This page is for running the engine yourself. It condenses the engine repo's [`RUNNING_LOCALLY.md`](https://github.com/agentxagi/valorbrain/blob/main/RUNNING_LOCALLY.md) — when in doubt, that file (and `/openapi.json` of your running instance) is the truth.

## The stack

| Layer | What | Default |
|---|---|---|
| Runtime | **Bun** 1.x (not Node; avoid the snap install — broken stdin breaks hooks) | — |
| Database | **PostgreSQL 18** | `:5433`, runtime via **PgBouncer** `:6432` |
| Extensions | `vector` (pgvector), `pgturbohybrid`, `pg_ripple`, `pg_deltax` | proprietary forks on GitHub |
| Engine | REST + MCP HTTP in one Bun process | `:7438` |
| Embedding | LFM2.5-Embedding-350M (1024d) | `:7997`, or any OpenAI-compatible cloud URL |
| Reranker | BGE-Reranker-v2-m3 cross-encoder | `:8096`, optional in dev (in-process fallback) |
| LLM | OpenAI-compatible gateway | `:8201/v1`, model via `VALORBRAIN_LLM_MODEL` |

**GPU is optional.** Without one, point `VALORBRAIN_EMBED_URL` / `VALORBRAIN_RERANK_URL` / `VALORBRAIN_LLM_URL` at cloud endpoints. Without the proprietary Postgres extensions the engine still boots in **fallback mode** (pgvector + BM25 via tsvector) — fine for dev, no full hybrid RRF or KG graph.

## Databases — rule number one

| Database | Use |
|---|---|
| `valorbrain` | **Production.** Real tenant data. Never run the test suite against it. |
| `valorbrain_test` | Test suite (hard requirement — the suite refuses a database not named `*_test*`) |
| `valorbrain_staging` | Staging engine on `:7439` |

Runtime connections go through PgBouncer (`:6432`); migrations and DDL go **directly to `:5433` as the `postgres` role**. The application role (`valorbrain_app`) runs under RLS and never does DDL. Permanent safety rule: no `TRUNCATE`/`DROP`/bulk `DELETE` without `WHERE tenant_id = ...` — RLS does not block `TRUNCATE`.

## Setup

```bash
# 1. clone + install
git clone https://github.com/agentxagi/valorbrain ~/valorbrain && cd ~/valorbrain
bun install

# 2. databases + migrations (idempotent; as postgres, never the app role)
sudo -u postgres env PGHOST=localhost PGPORT=5433 psql -c "CREATE DATABASE valorbrain;"
sudo -u postgres env PGHOST=localhost PGPORT=5433 psql -c "CREATE DATABASE valorbrain_test;"
bash scripts/apply-engine-migrations.sh              # applies pending, registers checksums
DATABASE=valorbrain_test bash scripts/apply-engine-migrations.sh

# 3. dev tenant (prints the api_token you will use as Bearer)
bun run src/valorbrain.ts provision-tenant --slug dev --name "Dev" \
  --admin-email you@example.com --plan solo --dry-run

# 4. serve
bun run src/valorbrain.ts serve                      # REST + MCP on :7438
```

The migration script creates `schema_migrations`, detects reused numbers, and registers checksums — migrations applied by hand bypass the inventory, and an inventory that lies is worse than none. Migrations are **additive**; the runtime skips DDL at boot by design (`VALORBRAIN_SKIP_SCHEMA_BOOTSTRAP`).

Copy `.env.example` to `.env` and fill in the contract:

| Variable | Purpose |
|---|---|
| `POSTGRES_*` / `POSTGRES_URL` | Runtime via PgBouncer `:6432`; migrations direct `:5433` |
| `VALORBRAIN_EMBED_URL` | Embedding endpoint (default `:7997`) |
| `VALORBRAIN_RERANK_URL` | Cross-encoder (default `:8096`); omit for the in-process fallback |
| `VALORBRAIN_LLM_URL` / `VALORBRAIN_LLM_MODEL` | Gateway and model name |
| `VALORBRAIN_API_TOKEN` | Bearer the server requires (stored SHA-256 only) |
| `VALORBRAIN_PUBLIC_URL` | **The URL your engine advertises in `/openapi.json` `servers[]`.** Set it before you put the engine behind a tunnel/proxy, or clients will be told to call `localhost` |
| `VALORBRAIN_DEV_TENANT_ID` | Tenant your unscoped local CLI calls assume |

## Services and ports

`systemctl list-units 'valorbrain*'` on a production host shows the full inventory. The load-bearing ones:

| Service | Port | Job |
|---|---|---|
| `valorbrain.service` | **7438** | Production engine (env via drop-ins in `/etc/systemd/system/valorbrain.service.d/`) |
| `valorbrain-staging.service` | 7439 | Staging engine (`valorbrain_staging` DB, `/etc/valorbrain/staging.env`) |
| `valorbrain-embed-worker.service` | — | Continuous embedding worker |
| `valorbrain-watcher.service` | — | File watcher + extract pipeline |
| `valorbrain-entity-worker.service` | — | Entity extraction + enrichment |
| `lfm2-embed.service` | 7997 | Embeddings (CUDA) |
| `bge-reranker.service` | 8096 | Reranker (CUDA) |
| `gliner-ner.service` | 8103 | NER (CUDA) |
| `valorbrain-opencode-go-gateway.service` | 8201 | LLM gateway |

The engine binds `127.0.0.1` by default. To expose it: put a tunnel or reverse proxy in front and set `VALORBRAIN_PUBLIC_URL` to the public origin — the live `/openapi.json` rewrites `servers[]` from it, and `/setup/instructions` stops telling clients to call `localhost`.

## Verify the running engine

```bash
curl -sS http://localhost:7438/healthz          # liveness, no auth
curl -sS http://localhost:7438/openapi.json | jq '.servers, .info["x-valorbrain-live-operations"]'
```

The spec served at `/openapi.json` is **generated from the process's route table at request time** — `x-valorbrain-live-operations` counts what this build actually registered, `x-valorbrain-missing-from-yaml` lists routes that exist in code but not yet in the written contract, and `/openapi.yaml` serves the same document as YAML. If your client and this spec disagree about a path, believe the spec.

## Staging without stopping production

`bash scripts/staging-up.sh` brings up a full engine on `:7439` with its own database and the **same engine role** (`valorbrain_app`, RLS, no BYPASSRLS) — so benchmarking and schema experiments don't shadow production statistics or locks. `--recriar` wipes the corpus, `--down` stops it, `--status` shows state. Any script that imports the store should run via `scripts/bun-staging.sh` so the root `.env` (which points at production) stays out of the process.

## Quality gates

Two benchmark gates ship with the engine (they cost LLM tokens and time — they are not unit tests):

| Gate | What it protects |
|---|---|
| `bun run gate:locomo` | Nightly LoCoMo recall floor (R@10 ≥ 0.90 by default; `gate:locomo:full` for the full SOTA run) |
| `bun run gate:beam` | Product accuracy on BEAM-100K via the AMB harness, with a fixed reader/judge pair so numbers stay comparable |

The unit-suite gate is `bun run test` against `valorbrain_test` — any failure is a regression; there is no tolerance band.

## Upgrades

1. Backup first: `bash scripts/backup-valorbrain.sh` (or `pg_dump`).
2. Pull, `bun install`.
3. `bash scripts/apply-engine-migrations.sh` — additive only, checksum-registered.
4. Restart the engine; check `journalctl -u valorbrain -p err` and `/healthz`.
5. After schema changes, sync the test database before running the suite (`bun run sync:test-db`).
