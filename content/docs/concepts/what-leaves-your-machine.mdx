Esta página descreve o tráfego **automático** que o `@valorbrain/connect`
(versão 0.9.0, protocolo de hook v2) instala em cada harness: o que os hooks
mandam sem o agente pedir. As chamadas de ferramenta MCP que o próprio agente
faz (`memory_store`, `memory_retrieve`…) levam o que o modelo decidir enviar e
não estão cobertas aqui.

Hooks instalados por versões anteriores passam para a 0.9.0 pelo self-heal
(abaixo), menos os do **Codex**: o self-heal não reescreve hooks do Codex sem
mudança de contrato, então uma instalação do Codex anterior à 0.9.0 continua
com os hooks da 0.8.1 até você rodar o instalador de novo (e confiar nos hooks
em `/hooks`). Enquanto isso, o `--checkpoint off` salvo não vale no Codex; só
`VALORBRAIN_CHECKPOINT=off` desliga o checkpoint ali.

Cada número abaixo vem do código-fonte. Quando o código não determina algo,
a página diz **não determinado no código**.

## Resumo

| Harness | Eventos com hook | O que sai por evento | Arquivo de config |
|---|---|---|---|
| Claude Code | `SessionStart`, `UserPromptSubmit`, `Stop` | início: ids; prompt: até 8.000 caracteres; stop: só contadores | `~/.claude/settings.json` |
| Codex | `SessionStart`, `UserPromptSubmit`, `Stop` | igual ao Claude Code | `~/.codex/hooks.json` |
| Gemini CLI | `SessionStart`, `BeforeAgent`, `AfterAgent` | igual ao Claude Code | `~/.gemini/settings.json` |
| Kiro | `SessionStart`, `UserPromptSubmit`, `Stop` (V3) ou `agentSpawn`, `userPromptSubmit`, `stop` (legado) | igual ao Claude Code | `~/.kiro/hooks/valorbrain.json` (V3) ou `~/.kiro/agents/valorbrain.json` (legado) |
| Cursor | `sessionStart`, `stop` | início: ids; stop: só contadores. Sem hook de prompt | `~/.cursor/hooks.json` |
| Grok CLI | `Stop` | só contadores | `~/.grok/hooks/valorbrain.json` |
| OpenCode | plugin `chat.message` | prompt: até 8.000 caracteres | `~/.config/opencode/plugins/valorbrain.ts` |
| Hermes Agent | plugin MemoryProvider: início, cada turno, compressão, fim de sessão | o prompt de cada turno; o **transcript da sessão (até 8 MiB)** só com opt-in (`--transcript on`) | `~/.hermes/config.yaml` + `~/.hermes/plugins/valorbrain/__init__.py` |
| Oh My Pi (OMP) | nenhum (no modo hospedado o connect não instala hook) | nada automático | `~/.omp/agent/.mcp.json` (só MCP) |

OpenClaw não é instalado pelo `@valorbrain/connect` e fica fora desta página.

## O cliente de hook comum

Claude Code, Codex, Gemini CLI, Kiro, Cursor, Grok e OpenCode rodam o mesmo
cliente: `npx -y @valorbrain/connect@0.9.0 hook <evento> --harness=<id>`. A versão
é fixa (nunca `latest`): o hook roda a cada prompt, então só uma versão revisada
entra na sua máquina. Ele lê o JSON que o harness entrega no stdin e envia
**somente** os campos abaixo.

### Endpoint

`POST https://valorbrain-api.valor.digital/api/v1/hooks/cue`, com
`Authorization: Bearer <token>` e `content-type: application/json`.

Se a rota responder 404 ou 405 (engine sem `hooks/cue`; o resultado fica em
cache por 6 horas) ou 403 (engine antigo que trata o POST como escrita), o
cliente usa o caminho legado: uma chamada MCP `memory_prepare` em
`POST https://valorbrain-api.valor.digital/mcp` com `message` (o prompt
cortado em 8.000 caracteres, ou `"session start"`) e `fast_mode: true`.

### Corpo por evento

| Momento | Campos enviados |
|---|---|
| Início de sessão | `harness`, `session_id`, `event: "session_start"` e `source` quando o harness manda esse campo |
| Prompt | `harness`, `session_id`, `event: "prompt"`, `prompt` (os primeiros **8.000 caracteres**) e `source` quando presente |
| Stop | `harness`, `session_id`, `event: "stop"` e `state` com cinco números: `turns`, `busy_ms`, `checkpoints`, `session_started_at`, `last_checkpoint_at` |

O stop não manda texto da conversa. Quando o servidor responde com um
checkpoint, o cliente entrega esse texto ao modelo do próprio harness, que
decide o que gravar pelo MCP. O que o modelo gravar sai por essa chamada MCP,
não pelo hook.

### Credencial

O token é procurado nesta ordem, e o primeiro encontrado vence:

1. `--token=` na linha de comando (só instalações anteriores ao protocolo v2;
   o self-heal migra para o arquivo).
2. Variável de ambiente `VALORBRAIN_TOKEN`.
3. A entrada **deste harness** em `~/.valorbrain/connect.json` (arquivo 0600,
   uma entrada por harness). É o token `vbm_…` que o instalador gravou.
4. `api_key` em `~/.valorbrain/config.json` (o arquivo da CLI).

A base da API é `--api=`, depois `VALORBRAIN_API_URL`, depois a base salva
com o token e, por fim, `https://valorbrain-api.valor.digital`. Sem token, o
hook não faz nenhuma chamada de rede e escreve uma linha no stderr.

### Ritmo

- **Síncrono, não fire-and-forget**: o harness espera a resposta, porque ela
  vira contexto. O cliente corta cada requisição em **4 s**
  (`VALORBRAIN_HOOK_TIMEOUT_MS` muda esse valor). O harness corta o processo
  em **10 s** (Gemini: 10.000 ms).
- **Início de sessão**: uma chamada. Um segundo início na mesma sessão em
  menos de **20 s** não chama a rede.
- **Prompt**: uma chamada por prompt. Prompt vazio não chama. Com o envio de
  prompt desligado para o harness (`--prompt off`, abaixo), o hook de prompt
  não chama a rede.
- **Stop**: na maioria dos stops nada sai. A decisão é local, e o cliente só
  chama o servidor quando um checkpoint está devido. Política padrão (a
  resposta do servidor substitui): no mínimo **3** turnos, ou **2** turnos
  somando **8 min** de trabalho; intervalo mínimo de **10 min** (nunca menos de
  1 min); no máximo **6** checkpoints por sessão. Stop sem `session_id` não
  chama.
- **Limite no servidor**: **300** chamadas a cada **10 min** por token
  (`VALORBRAIN_HOOK_CUE_MAX_PER_10MIN` no engine).
- Qualquer erro sai com código 0 e no máximo uma linha no stderr; o prompt
  nunca é bloqueado pelo hook.

### Tráfego de manutenção (self-heal)

Toda execução do hook também tenta um self-heal, limitado a uma vez a cada
**6 horas** por máquina (marcado em `~/.valorbrain/connect-state.json`;
`VALORBRAIN_HEAL_INTERVAL_MS` muda o intervalo) e a **2,5 s** de espera no
caminho do hook:

- `GET https://valorbrain-api.valor.digital/setup/artifacts?agent=<id>&hooks=2`,
  sem credencial. O manifesto só é usado se trouxer uma assinatura ed25519
  válida de uma das chaves embutidas no connect (a ativa ou a reserva;
  cabeçalhos `X-ValorBrain-Manifest-*`; a chave pública em uso está em
  `/setup/manifest-keys`); sem ela, nada é escrito.
  Se o contrato mudou, reescreve localmente as regras e os hooks do harness (o
  Codex fica fora da migração automática de hooks), **menos** os arquivos que
  você editou à mão: esses ficam como estão e o aviso vai para o stderr e para
  `~/.valorbrain/connect.log`. Rodar o instalador de novo mostra o diff e
  pergunta antes de sobrescrever.
- `POST https://valorbrain-api.valor.digital/api/v1/runtimes/register` com o
  token, em até 2,5 s. Envia `runtime_key`
  (`<harness>:<hostname>:<caminho do home>`), `agent_platform`, `display_name`, `hostname`,
  `plugin_version: "0.9.0"` e `capabilities` (harness, versão do contrato
  instalada, `connector: "connect"`, `self_heal: true`, protocolo de hook).

A mesma declaração sai uma vez ao final de cada instalação.

### Durante a instalação

Sem `--token`, o instalador abre a aprovação do computador:
`POST https://valorbrain.valor.digital/api/v1/cli/device/code` com
`client: "connect"`, a lista de harnesses, `device_label`
(`<hostname> (<sistema operacional>)`, até 80 caracteres) e `install_id` (16 caracteres hexadecimais
aleatórios guardados em `~/.valorbrain/install-id`). Em seguida consulta
`/api/v1/cli/device/token` até a aprovação.

Fonte: `/www/valorbrain-cli/packages/connect/hook.mjs`,
`/www/valorbrain-cli/packages/connect/index.mjs`,
`/www/valorbrain-cli/packages/connect/login.mjs`,
`/opt/valorbrain/src/hooks/cue.ts`, `/opt/valorbrain/src/server.ts`

### Hermes Agent

O Hermes não usa o cliente de hook comum. O connect grava um plugin
MemoryProvider em Python que, sem o binário `valorbrain` local, roda os hooks
no engine.

| | |
|---|---|
| Eventos | início de sessão (`session-bootstrap`); cada turno com 5 ou mais caracteres (`context-surfacing`, em thread de fundo); compressão (`precompact-extract`, e `postcompact-inject` no turno seguinte); fim de sessão (`decision-extractor`, `handoff-generator`, `feedback-loop` em paralelo) |
| O que sai | nos turnos: `hook`, `sessionId`, `hookEventName` e o `prompt` inteiro (sem corte no cliente). O **transcript da sessão** (`~/.hermes/valorbrain-transcripts/<sessão>.jsonl`, até **8 MiB**, cada mensagem do usuário e cada resposta do assistente) **só sai com opt-in**: sem ele o plugin nem grava o arquivo, e a extração de fim de sessão e de compressão não roda |
| Endpoint | `POST <VALORBRAIN_ENGINE_URL>/api/v1/hooks/run`. Fallbacks: `GET /api/v1/memory/working-context?format=md` no início e `POST /api/v1/memory/prepare` (prompt, `recall_budget: 600`, `fast_mode: true`) no turno |
| Credencial | `Authorization: Bearer` com `VALORBRAIN_API_TOKEN`, que o instalador grava em `env` de `~/.hermes/config.yaml` (o mesmo `vbm_…` do MCP). Cabeçalhos extras: `X-Source-Agent`, `X-Source-System` (padrão `hermes`) e, se definidos, `X-Tenant-ID` e `X-User-ID` |
| Ritmo | timeouts: 30 s nos hooks de ciclo de vida, 90 s no `context-surfacing`, 5 s nas chamadas REST |
| Desligar | prompt: `npx -y @valorbrain/connect --harness hermes --prompt off` ou `VALORBRAIN_SEND_PROMPT=off` no `env` de `~/.hermes/config.yaml` (sem recall por turno). Transcript (opt-in): `--transcript on` ou `VALORBRAIN_SEND_TRANSCRIPT=on`. Tudo: `npx -y @valorbrain/connect --harness hermes --remove` (remove `mcp_servers.valorbrain`, `memory.provider`, as chaves de `env` e o plugin); ou troque `memory.provider` em `~/.hermes/config.yaml` |

O Hermes não tem hooks no manifesto: `--mcp-only` não muda nada nele. O plugin
de memória continua instalado e envia o prompt de cada turno; para parar, use
`--prompt off` (ou `--remove`, que tira tudo).

Outras chamadas do plugin: `GET /foundations?limit=10` e `GET /health` no
início; `POST /api/v1/runtimes/register` no início (com `hostname`);
`POST /api/v1/runtimes/heartbeat` no máximo a cada 300 s; e
`GET /setup/instructions` quando a mensagem pede setup do ValorBrain.

Contextos que não são o principal (subagente, cron, flush) não gravam
transcript nem rodam a extração de fim de sessão e de compressão.

O engine aceita no máximo 40 chamadas de `hooks/run` a cada 10 min por tenant.

Fonte: `/opt/valorbrain/src/hermes/__init__.py`,
`/opt/valorbrain/src/harness/adapters.ts` (adapter `hermes`),
`/www/valorbrain-cli/packages/connect/index.mjs` (`mergeYaml`)

### Oh My Pi (OMP)

No modo hospedado, o connect grava só a entrada MCP
(`~/.omp/agent/.mcp.json`) e as regras (`~/.omp/AGENTS.md`). A ponte de hooks
do OMP depende do binário local do engine e não é instalada. Não há tráfego
automático além das ferramentas MCP que o agente chamar.

Fonte: `/opt/valorbrain/src/harness/adapters.ts` (adapter `omp`)

## O que não sai

Isto vale para o cliente de hook comum (todos os harnesses acima, menos o
Hermes):

- **Transcript**: o cliente não lê o arquivo de transcript. Além dos três
  corpos acima, do fallback legado e do self-heal, ele não envia nada. A
  leitura de transcript existe só para hooks de extração legados, que o
  instalador do protocolo v2 não liga.
- **Diretório de trabalho e o resto do payload**: `cwd`, `transcript_path` e os
  demais campos que o harness entrega ficam na máquina. O `cwd` só entra num
  hash local que identifica a sessão.
- **Respostas do assistente e saídas de ferramentas**: não fazem parte de
  nenhum corpo enviado.
- **Token na linha de comando**: no protocolo v2 o token fica em
  `~/.valorbrain/connect.json` (0600), nunca no argv do hook.

No servidor, a trilha de leitura do `hooks/cue` guarda só o hash da consulta,
não o texto.

Fonte: `/www/valorbrain-cli/packages/connect/hook.mjs`,
`/opt/valorbrain/src/harness/adapters.ts`, `/opt/valorbrain/src/server.ts`,
`/opt/valorbrain/src/access-tracker.ts`

## Como desligar

- Tudo: `npx -y @valorbrain/connect --remove`. Desfaz a instalação inteira dos harnesses
  detectados: entradas MCP, regras, hooks e as credenciais em
  `~/.valorbrain/connect.json`.
- Um harness: `npx -y @valorbrain/connect --harness <id> --remove` (o mesmo, só para ele).
- Só os hooks, mantendo o MCP e as regras: rode a instalação de novo com
  `--mcp-only` (`npx -y @valorbrain/connect --token <vbm_…> --harness <id> --mcp-only`). Nada sai por turno; rodar de
  novo sem `--mcp-only` põe os hooks de volta. Hooks que você editou à mão só
  saem com `--force` ou com um sim na pergunta. A nova execução precisa do
  token (`--token <vbm_…>`, como na instalação): sem ninguém no teclado, como
  no shell de um agente, o connect para sem ele. No Hermes, que não tem hooks,
  a flag não muda nada (o plugin continua enviando o prompt); numa instalação
  hospedada o OMP não recebe hooks do connect (a ponte de hooks do OMP é
  self-hosted).
- Só o checkpoint do stop, por harness: `npx -y @valorbrain/connect --harness <id> --checkpoint off`
  (grava `checkpoint: false` na entrada do harness; `--checkpoint on` religa).
  Na máquina inteira: `VALORBRAIN_CHECKPOINT=off` (ou `0`, ou `false`) no
  ambiente do harness, que vence o arquivo nos dois sentidos. No Gemini CLI só
  o `--checkpoint off` funciona; no Codex instalado antes da 0.9.0, só a
  variável, até reinstalar.
- Só o prompt, por harness: `npx -y @valorbrain/connect --harness <id> --prompt off`
  (grava `send_prompt: false` na entrada do harness em
  `~/.valorbrain/connect.json`; `--prompt on` religa). Na máquina inteira:
  `VALORBRAIN_SEND_PROMPT=off` no ambiente do harness (o Gemini CLI sanitiza o
  ambiente; nele, use o `--prompt off`). Sem o prompt, o início de sessão e o
  checkpoint continuam; o recall por prompt para.
- Transcript do Hermes: desligado por padrão; liga com
  `npx -y @valorbrain/connect --harness hermes --transcript on`.
- À mão: apague as entradas cujo comando contém `@valorbrain/connect` no
  arquivo do harness (tabela abaixo). Apagar só `~/.valorbrain/connect.json`
  não basta se `~/.valorbrain/config.json` tiver `api_key`, porque o hook usa
  essa chave como último recurso.

## Como verificar

- `npx -y @valorbrain/connect --status` mostra, por harness, se os hooks estão
  ligados, em qual protocolo e para qual engine, e o modo (`mcp-only` ou
  `hooks`).
- `npx -y @valorbrain/connect --token <vbm_…> --dry-run` mostra o que seria
  escrito, sem escrever nada.
- Os arquivos que você pode abrir:

| Harness | Onde ficam os hooks |
|---|---|
| Claude Code | `~/.claude/settings.json` → `hooks` |
| Codex | `~/.codex/hooks.json` |
| Gemini CLI | `~/.gemini/settings.json` → `hooks` |
| Kiro | `~/.kiro/hooks/valorbrain.json` (V3) ou `~/.kiro/agents/valorbrain.json` (legado) |
| Cursor | `~/.cursor/hooks.json` |
| Grok CLI | `~/.grok/hooks/valorbrain.json` |
| OpenCode | `~/.config/opencode/plugins/valorbrain.ts` |
| Hermes Agent | `~/.hermes/config.yaml` e `~/.hermes/plugins/valorbrain/__init__.py` |
| Todos (credencial) | `~/.valorbrain/connect.json` |

Veja também [Tokens](/docs/concepts/tokens) e [Hosts](/docs/concepts/hosts).
